# Сквозное тестирование (End-to-End / E2E Tests) WAF

В этой директории находятся сквозные (E2E) тесты для Web Application Firewall (WAF). Эти тесты проверяют систему в сборе, работая по принципу «черного ящика» (black-box testing) над полностью развернутым окружением.

---

## Особенности E2E-тестов

1. **Полная интеграция**: Тесты взаимодействуют со всеми сервисами WAF, включая прокси-сервер Angie, ClickHouse, Centrifugo, Redis, PostgreSQL и бэкенд-процессы.
2. **Реальные сценарии**: Имитируют поведение реальных пользователей (регистрация, настройка доменов, 2FA) и реальных злоумышленников (SQL-инъекции, XSS-атаки, подбор паролей).
3. **Автоматическая разметка**: Благодаря кастомному хуку в `tests/conftest.py`, все файлы в этой папке автоматически получают маркер `@pytest.mark.e2e`.

## Подготовка окружения

E2E-тестирование требует полной сборки и запуска всего стека WAF в Docker.

### Шаг 1: Сгенерируйте конфигурации окружения

```bash
# Генерация .env файлов на основе шаблонов (выполняется один раз)
./scripts/generate-env.sh
```

### Шаг 2: Соберите и запустите стек сервисов

Запустите контейнеры в фоновом режиме с принудительной пересборкой образов:

```bash
docker compose up -d --build
```

Убедитесь, что все ключевые сервисы (postgres, clickhouse, centrifugo, redis, backend, angie, crowdsec) находятся в статусе `running`:
```bash
docker compose ps
```

## Запуск E2E-тестов

### 1. Запуск всех сквозных тестов

Вы можете запустить тесты по маркеру `e2e` или по пути к папке:

```bash
# Запуск по маркеру
pytest -m e2e

# Запуск по пути (с подробным выводом)
pytest tests/e2e/ -v
```

### 2. Запуск отдельной категории тестов

Например, для проверки исключительно правил фильтрации атак ModSecurity:

```bash
pytest tests/e2e/modsecurity/ -v
```

Или для проверки интеграции с CrowdSec:

```bash
pytest tests/e2e/crowdsec/ -v
```

## Отладка и просмотр логов

Если E2E-тест падает, самым надежным способом понять причину является просмотр логов контейнеров:

```bash
# Просмотр логов бэкенда
docker compose logs backend -n 100 --no-log-prefix

# Просмотр логов прокси Angie (помогает увидеть блокировки ModSecurity)
docker compose logs angie -n 100

# Отслеживание логов CrowdSec в реальном времени
docker compose logs crowdsec -f
```

---

## Завершение работы и очистка

После завершения тестов вы можете остановить контейнеры и очистить созданные тома (volumes) баз данных, чтобы вернуть систему к исходному состоянию:

```bash
docker compose down -v
```
